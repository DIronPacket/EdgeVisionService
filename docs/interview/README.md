# docs/interview/ —— 面试问答手册

> 用途：把这个仓库**真实做过什么、为什么这么做、哪里还没做完**讲清楚。
> 原则：**只讲代码里能指到行号的东西**；没做过的就说"还没做/只知道思路"。

## 1. 这篇文档怎么来的

它不是"项目介绍"，而是把前三个目录的内容**换一种讲法**：

| 素材 | 转换成的部分 |
| --- | --- |
| [../ARCHITECTURE.md](../ARCHITECTURE.md) + [../STATUS.md](../STATUS.md) | §1 项目速览、§2 高频问题 |
| [../history/BUG_CASES.md](../history/BUG_CASES.md) | §3 核心问题（"你真的想过为什么"）、§4 深入问题 |
| [../ops/CRASH_DUMP.md](../ops/CRASH_DUMP.md) + V4L2/mmap 代码 | §5 这个项目到底碰没碰内核 |
| 源码里的 C 风格代码（`MemPool.cpp`、`v4l2_capture.cpp`、`crash_handler.cpp`） | §6 能练 C 语言熟练度的 8 个落点 |

## 2. 内部结构（[INTERVIEW.md](INTERVIEW.md)）

| § | 内容 | 用的时候 |
| --- | --- | --- |
| 0 | 三段话（30 秒 / 2 分钟 / 5 分钟版本） | 面试开场自我介绍，**先背这个** |
| 1 | 项目速览（一图流） | 答任何问题前在脑里过一遍 |

| 7 | 4 周准备路线 | 临阵磨枪 |
| 8 | **诚实清单**（哪些没做、只知道思路） | 被问到未完成功能时 |
| 9 | 速查表（问题 → 代码位置 → 档案） | 面试前 10 分钟过一遍 |

## 3. 三条使用纪律

1. **别背结论，背代码位置**：说"`MemPool::release()` 里引用计数减到 0 才 push 回 `free_list_`"比说"我们做了引用计数"强十倍。
2. **区分"做过 / 验证过 / 只是设计过"**：这个仓库里三者都有（例如崩溃采集=做过且验证过；三进程拆分=只设计过）。混着说一旦被追问就崩。
3. **§8 诚实清单要主动用**：面试官更怕"什么都能做"的人。主动说"录像只做了选型，没落地"是加分项。

## 4. 与其他文档的引用关系

```text
interview/INTERVIEW.md  ──引用──▶ ARCHITECTURE / STATUS（事实）
                        ──引用──▶ history/BUG_CASES.md §2.x（案例）
                        ──引用──▶ history/TESTLOG.md §5.x（证据："已验证"的出处）
                        ──引用──▶ ops/CRASH_DUMP.md §1–§3（内核链路）
```
凡是 `INTERVIEW.md` 里写「已验证」的，必须能在 `TESTLOG.md` 找到对应记录；写不出来就改成「按设计应该可行，尚未实测」。
